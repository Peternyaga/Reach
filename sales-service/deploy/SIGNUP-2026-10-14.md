## Server

1. Pause the existing Fieldwork Reach poller on the Windows computer while upgrading.
2. Upload `fieldwork-reach-upgrade.zip` to `/home/supashop/domains/reach.vumbualabs.com/` in DirectAdmin, **outside** `public_html`.
3. Open the DirectAdmin terminal and run this single command:

```bash
cd /home/supashop/domains/reach.vumbualabs.com && unzip -oq fieldwork-reach-upgrade.zip -d fieldwork-upgrade && bash fieldwork-upgrade/install-upgrade.sh
```

Wait for `Release installed` and save the backup path printed by the installer. The installer stops if the database backup fails, preserves private production configuration, backs up application files and runs the repeatable migration before copying the website. No existing accounts, workspaces or data are deleted. This signup change adds `oauth_codes.auth_version`; existing unexchanged codes must restart linking. Existing active grants remain valid. If the command fails, leave the poller paused and investigate the error and backup before retrying. After the checks below and the plugin refresh, resume the poller.

After deployment:

1. In a private browser, open `https://reach.vumbualabs.com/signup`. Create a disposable workspace and owner with an unused email. Check that it starts with General and no other workspace's leads or team.
2. Sign out and sign back in. Existing invited accounts should still sign in normally. Create an invitation from an existing workspace to confirm that joining a team remains separate from creating a workspace.
3. Start plugin connection with no browser login. Choose Create account, create another disposable workspace, sign in and review consent. Approve only needed scopes; verify `get_profile` and `list_projects` identify that new account.
4. Check the public `/connect-codex` guide, desktop layout and mobile signup. Check an existing account's leads and mailbox/project selection.

There is no in-app workspace deletion. Use accounts intended for ongoing acceptance testing, or have the operator deliberately clean up test-only accounts after review; do not delete real data. The local automated tests already cleaned their own fixtures.

Restart the desktop app and verify in a fresh chat. Existing valid OAuth grants and poller pairings do not need rotation. The poller scripts were not changed by the signup implementation.

## Limits

Email ownership verification, CAPTCHA and automated owner recovery are not implemented. Each email maps to one account in one workspace. Application limits are 5 signup submissions per direct IP/hour and 100 globally/hour; login is 40 per IP and 8 per email per 15 minutes. Add hosting-level abuse controls if public traffic warrants them. Account setup accepts 12–72 bytes; old account passwords keep working. No outbound email is sent by registration.
