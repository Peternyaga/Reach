## Upgrade the server yourself

1. Pause the existing Fieldwork Windows scheduled poller during this coordinated server/plugin upgrade. Avoid workspace edits while the upgrade runs. Preserve its DPAPI pairing/configuration; do not uninstall or re-pair it.
2. Upload `sales-service/publish/fieldwork-reach-upgrade.zip` to `/home/supashop/domains/reach.vumbualabs.com/` outside public_html. Run the existing backup-first installer in DirectAdmin:

```bash
cd /home/supashop/domains/reach.vumbualabs.com && unzip -oq fieldwork-reach-upgrade.zip -d fieldwork-upgrade && bash fieldwork-upgrade/install-upgrade.sh
```

The installer backs up database/site/backend and the existing private mail key, preserves private configuration, and applies repeatable migrations. Keep the backup and mail.key together. It restores old files if installation fails; schema changes require a deliberate database restore for rollback. After a failed migration, leave the poller paused and investigate or restore before resuming. Do not upload local config, var, test fixtures or credentials.

3. Reload every open website session once. Select each intended project in the sidebar. Open Connected apps → Your email accounts and choose **Sender for [project]**. The existing connected mailbox is retained as an account, but its project sender is deliberately unassigned. Each user chooses their own sender for every project; another user's private mailbox cannot be selected. More accounts can be connected through the collapsed SMTP form. Existing passwords stay encrypted and are not shown; leave blank when editing to preserve one.
4. Verify leads, Intake, Pipeline, Schedule and dashboard totals switch together. Agent activity must default to that project; All projects must label the project on each report. Opening a different project's report must switch the context. A lead move keeps its history/tasks/opportunities and sends pending agent work to human review.
5. Review any legacy pending email task and queue a new task with explicit recipient/sender permission if still intended. Old email consent is not upgraded silently. Changing a sender, recipient or SMTP account revision also requires fresh consent. Test real mail only to a mailbox you control and only when deliberately authorized; no real mail was sent during local verification.

`publish/fieldwork-reach-plugin-0.4.7.zip` contains the hosted plugin source directory. Extract it into `plugins/sales-workspace-hosted` in the existing Vumbua Labs marketplace repository, review the diff, then commit/push yourself. Preserve the marketplace catalogue. On each worker computer, after publication:

```powershell
codex plugin marketplace upgrade vumbua-labs
codex plugin add sales-workspace-hosted@vumbua-labs
```

Restart Codex and refresh the existing poller with the refreshed plugin's `scripts/install-poller.ps1 -Accept -WorkspaceRoot <existing workspace>` per its README, preserving its pairing. Verify the scheduled task's enabled state before resuming it. No new OAuth scope is added in this release; existing email:send authorization is still separately required. Old cached tools without project_id will fail closed until refreshed.

Before resuming the poller, use a fresh chat to list projects and call list_agent_work with project_id=all. Returned work must carry project_id. For any authorized item, every subsequent read/write must carry that same project ID. A browser project switch must not retarget its work. The narrow ready endpoint still returns only a boolean and empty queues incur no model call. Multiple worker PCs still have no distributed lease; use the existing single worker.

`publish/fieldwork-local-plugin-projects.zip` contains the updated local stdio plugin source for local installations. Its record tools require project_id; move_lead_project additionally requires source_project_id. The hosted plugin remains the production workflow.

## Post-upgrade checks

Confirm HTTPS login, scoped lists/counts, per-project sender display, Agent activity selected/All behavior, current-version move protection, preserved history and OAuth scope behavior. Keep the poller paused if required tools are unavailable or authorization fails. Local fake transport and isolated OAuth testing cannot confirm provider deliverability or production migration. Never blindly resend a sending or needs_check row.
